# Smart Note UI 规则

这份文档是这个项目界面数值的唯一来源。写样式、改布局、加新页面之前先看这里，
不要在页面里临时决定字号、间距或颜色。token 定义在 `src/styles/tokens.scss`。

## 0. 基调

- 轻、克制、高信息密度，接近 iOS 原生列表的观感。
- 主要形态是 iPhone 上的 H5；小程序端跟随同一套规则。
- 数值一律取 token。**允许的裸值只有这几个**：`0`、`1px` 描边（用 `$hairline`）、
  百分比、`vh/vw`、`env(safe-area-inset-*)`、`1.4` 之类的纯数字行高。其他一律走 token。

单位说明：`tokens.scss` 里的数值是 Taro 的 750 设计稿空间，**设计值 ÷ 2 ≈ 375pt 屏上的 CSS px**。
下面提到的 pt 都是指这个换算后的视觉尺寸。

## 1. 间距

只用 6 级：`$space-1..6` = 4 / 8 / 12 / 16 / 24 / 32 pt。

- 页面左右边距：24pt（`$space-5`），由 `.app` 的 padding 统一给，页面内部不要再各自加左右边距。
- 同一列表里相邻两行的上下 padding 必须相等。出现 16/15 这种差 1px 的写法就是手感不齐的根源。
- 分组之间用 24pt（`$space-5`），分组内部元素之间用 8/12pt。
- 圆点、图标、文字之间的横向间距用 8pt（`$space-2`）或 12pt（`$space-3`），不要写 13px、17px。

## 2. 字号

| 角色 | token | 视觉大小 | 字重 | 颜色 |
| --- | --- | --- | --- | --- |
| 页面大标题 | `$text-brand` | 26pt | bold | `$text-primary` |
| 详情 / Sheet 标题 | `$text-page` | 20pt | semibold | `$text-primary` |
| 一级项目标题、区块标题 | `$text-title` | 18pt | medium | `$text-primary` |
| 二级 / 三级节点标题 | `$text-item` | 16pt | regular | `$text-primary` |
| 正文、输入框 | `$text-body` | 15pt | regular | `$text-primary` |
| 日期 / 进度 / 次要说明 | `$text-meta` | 13pt | regular | `$text-secondary` |
| 数量 / 辅助标签 | `$text-caption` | 11pt | regular | `$text-tertiary` |

同一层级的标题字重保持一致：二级和三级都是 regular，靠缩进区分，不靠加粗。

## 3. 颜色

- 文字只有三档：`$text-primary` / `$text-secondary` / `$text-tertiary`。
  再弱一档只有完成态用 `$text-done`。
- 完成态绿只有 `$accent-done` 一个；危险操作只有 `$danger` 一个。
- 背景色只有 5 个 token。`$surface-group` 是**唯一的层级底色**，不要再引入第二层灰。

## 4. 项目树

结构是 项目 → 事项 → 子项，允许更深。

- **层级主要靠缩进表达**：每一级缩进 24pt（`$space-5`）。
- 展开区域可以有一层 `$surface-group` 底色 + 一条左侧竖线，但**底色要很淡**，
  而且整个区域是一块连续的底，不要每行一块灰矩形。
- 不要同时用「底色 + 边框 + 阴影」三件事表达同一层关系，最多一个底色 + 一条竖线。
- 同一分组内部的分割线用 `$divider-subtle`，结构分隔用 `$divider`。
- 每一行的形态统一为：`圆圈 | 标题 + 次要信息 | 展开箭头`，三段的间距固定，
  不要某个页面多一个图标、某个页面少一个。

### 行内元素职责

| 位置 | 点击行为 |
| --- | --- |
| 圆圈 `○ / ✓` | 切换完成状态（叶子改自己，父级批量改后代叶子） |
| 标题 / 行主体 | 打开该对象自己的详情 |
| 展开箭头 | 只负责展开 / 收起 |
| 左滑 | 复制 / 删除 |

这几块必须各自 `stopPropagation`，不能互相触发。

### 次要信息行

每一行标题下面的次要信息只有两段，顺序固定：

`0/1 · 10-30`

- 进度在前、日期在后，中间用 `·` 分隔（前后各一个空格）。
- 进度只在该节点有后代时出现，日期只在有截止时间时出现；两段都没有就整行不渲染。
- 不要给这两段加图标前缀。`⑂`、`▦` 这类字符在中文字体里经常没有字形，会渲染成方框。
- 项目行和事项行共用同一档字号 `$text-meta` 和同一档颜色 `$text-secondary`，
  不要给项目行单独降一档，否则同一个信息在两行之间会看起来像两种东西。

## 5. 完成态

全项目只有一套，抽在 `app.scss` 的 `.done` 规则里：

- 左侧圆圈变 `✓`，颜色 `$accent-done`。
- 标题加删除线，颜色降级到 `$text-done`。
- 说明文字、日期、进度一起降到 `$text-tertiary` 一档。
- 项目 / 事项 / 子项共用同一套。**不要按节点类型分支判断**，只看算出来的 `completed`。

数据模型上完成状态只有一个来源：叶子节点存自己的 `completedAt`，父级由后代叶子推导
（`src/domain/aggregate.ts`）。任何页面都不要再存第二份完成状态。

## 6. Bottom Sheet

项目、事项、子项详情统一用 Bottom Sheet，不做整页跳转。

- 顶部固定三段：`‹ 返回` / 标题 / 右侧操作。
- 右上角的「关闭」表示**结束本次编辑**，不是把任务标记为完成。完成只由圆圈控制，两者语义不能混。
- 管理类操作（复制 / 删除）收进右上角 `···`，不要散在正文里。
- Sheet 之间可以叠加，关闭时回到实际打开它的那一层，不要按数据父子关系强制跳转。
- 圆角 `$radius-lg`，背景 `$surface-sheet`。

## 7. 可点区域

任何可点的元素，命中区域不小于 `$touch-min`（44pt）。列表里的圆点按「纵向 44pt + 横向 32pt」执行：
纵向靠行高保证，横向是因为严格的 44pt 会把每一行的标题整体右移 30pt 以上，得不偿失。

- 圆圈视觉大小可以小，但外面要留够命中区；四级的圈尺寸必须一致。
- 列表行整行可点时，行高 ≥ 44pt 即满足。
- 展开箭头、`···`、左滑按钮同样按这个尺寸给。

## 8. 状态反馈

- 完成 / 取消完成、展开 / 收起、切换筛选都要立刻反映到界面，不需要重新进页面。
- 破坏性操作必须二次确认，确认文案里写清后果；低频操作放 `···`。
- 空列表给一句引导文案，不要留纯空白。

## 9. 改完 UI 的自查

按 `skills/ui-design/SKILL.md` 里的清单过一遍。最低要求：

1. 左右边缘和同级元素对齐一致。
2. 同级元素间距一致，两行之间的上下 padding 对称。
3. 所有字号、间距、颜色都能在上面的表里找到出处，没有新的裸值。
4. 没有用两种以上的手法重复表达同一层层级。
5. 可点区域 ≥ 44pt。
6. 完成态、展开态、空状态、危险操作四种状态都覆盖到了。

## 10. 现状与迁移

`src/app.scss` 是历史文件，还有一批没迁到 token 的裸值（主要是日历、设置、计量样式）。
处理原则是**改到哪、迁到哪**：只要你动了某个选择器，就顺手把它那一行的字号 / 间距 / 颜色换成 token。
不要为了迁移而整篇重写，也不要在旧值旁边再复制一套新值。

已经迁移的区块：项目列表、展开树、事项 / 子项行、Bottom Sheet 骨架、完成态、筛选与左滑操作。

`src/App.tsx`、`src/ui/`、`src/index.css` 是迁移前的旧网页界面，不参与 Taro 打包，不要改它们。
